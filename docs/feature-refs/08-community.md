# 8 社区与社会化（4 条 v1 + 3 条新增）

> **一句话结论**：本域 v1 的 4 条里，3 条（超展开 / 时间胶囊 / 吐槽）在 v1 附录 B 已判定「不做」，本轮维持该结论并给出**源码级的边界依据**：全仓 grep `超展开|时间胶囊|吐槽` 命中 0，`data/remote/` 下也没有对应的 API 客户端，说明这不是「没做」，而是**从来没有进入过架构**。真正有空间的是 8.4：现在的分享管线只支持**单作品**（`ui/share/ShareFlow.kt` 的 `saveAndGetUri` + `buildShareIntent`），而「把我这一季看的 20 部排成一张图」是这个应用最自然的社交出口，且不需要服务端。

## 8.1 逐条详解

### 8.1 超展开（社区话题流）
- **现状**｜无｜`grep -r '超展开' app/src/main` 命中 0；`data/remote/bangumi/` 只接了条目/剧集/角色/人物/关联，没有 `/group` 或话题端点。
- **提升**｜无功能收益。若强做，收益是「不离开应用就能看讨论」，代价是引入内容展示、举报/屏蔽、缓存与合规问题，与 v1 附录 B-13~B-21 的结论冲突。
- **原理**｜如果**将来**翻案，最小可行形态是「只读 + 只在详情页嵌入一个话题区块」：`GET /v0/subjects/{id}/comments` 之类按条目拉取，走 `data/refresh/RefreshCoordinator` 的软 TTL（例如 6 小时），失败静默隐藏整块，永不做发帖。**本轮不做**：这条路径需要产品决策（是否承担 UGC 展示责任），不是工程决策。
- **效果**｜本轮无。翻案后的效果是详情页多一个「讨论」折叠区块。
- **参考**｜`xiaoyvyv/bangumi`（R3）的只读社区实现只作对照 `[README]`（仓库 >50MB，本轮未读到源码）。
- **成本/风险**｜L｜合规与内容治理；一旦展示 UGC 就要处理屏蔽词与举报入口。
- **优先级**｜**不做**（维持 v1 附录 B 结论）

### 8.2 时间胶囊
- **现状**｜无｜本地时间线（`ui/stats/TimelineSection.kt`）记录的是**我自己的操作**，与 Bangumi 账号的时间胶囊（他人的动态流）完全不同概念。
- **提升**｜无。本地的「观看时间线」已经能回答「我什么时候看了什么」，账号动态属于社交信息流。
- **原理**｜若翻案需 OAuth 后的 `/v0/users/{id}/timeline` 只读拉取 + 分页缓存；纯客户端下没有推送，只能手动刷新，体验弱于网页版。
- **效果**｜本轮无。
- **参考**｜无（未找到可核的只读实现）。
- **成本/风险**｜M｜与本地时间线混淆的风险大于价值。
- **优先级**｜**不做**

### 8.3 吐槽 / 短评浏览
- **现状**｜无｜详情页的「我的评价」是本地字段，没有他人吐槽的展示。
- **提升**｜弱。这个应用的价值是「我记了什么」，不是「别人说了什么」；且与他人评分同时展示会干扰个人评分（与 v1 §1.9「评分前隐藏他人评分」的初衷相反）。
- **原理**｜技术上与 8.1 同源（评论端点 + 只读渲染），成本主要在内容治理。
- **效果**｜本轮无；若翻案，建议做成**评分提交后才可见**（与 1.9 同一开关控制）。
- **参考**｜无。
- **成本/风险**｜M｜同上。
- **优先级**｜**不做**

### 8.4 可分享清单
- **现状**｜部分｜`ui/share/` 有 `ShareBitmapHost.render / renderPoster`、`ShareCardRenderer`、`ShareFlow.saveAndGetUri / buildShareIntent / buildChooser`，但入口只有**单作品**分享卡；没有「把我的一个分区 / 本季清单发出去」的产物。
- **提升**｜用户：把「我这季看了 20 部」变成一张可直接发群里的图，是零服务端条件下最强的社交出口，也是应用的自然传播渠道。工程：把分享从「一个作品」抽象成「一个数据集」，后面 8.5/8.6/8.7 都能复用同一套渲染与分页。
- **原理**｜把 `ShareCardData` 泛化为 `ShareDocument(title, subtitle, blocks: List<ShareBlock>)`，`ShareBlock` 四类：`PosterGrid(items, columns=3)`、`MetricRow(list)`、`Quote(text)`、`Footer(qr/url)`。渲染仍走 `ShareBitmapHost`（Compose 渲染到 Bitmap），按内容高度切成多页 PNG；分享时 `ACTION_SEND_MULTIPLE`。
- **效果**｜作品库多选后出现「生成清单卡」：选择版式（网格 3×4 / 杂志 / 极简）→ 预览可左右翻页 → 一次分享多张；底部小字「Niriko · 2026 秋」。
- **参考**｜`KotatsuApp/Kotatsu@devel:app/src/main/kotlin/org/koitharu/kotatsu/core/util/ShareHelper.kt` `[码]`（已核实路径存在）——它把「分享图片/文字/链接/进度的选择」收在一个 helper 里；本项目 `ui/share/ShareFlow.kt` `[码]` 已有 FileProvider + chooser 的完整链路。
- **成本/风险**｜S｜大清单（100+ 部）一次渲染出 20 页会 OOM → 必须限制每页数量并流式渲染，逐页写盘后再释放。
- **优先级**｜**P1**

## 8.9 本域新增候选（发散）

### 8.5 分区清单海报（多页 + 可选页眉）
- **现状**｜无 · 新提出｜8.4 的落地形态。现在 `SharePosterCard` 只渲染单作品。
- **提升**｜Niriko 的库是「分区 + 标签」组织的，但没有任何方式把这种组织**展示给不装应用的人**。分区海报把「我的品味结构」变成可传播的产物，而不是 20 张孤立封面。
- **原理**｜输入 = `LibraryFolder` + 成员列表 + 排序偏好；布局 = 页眉（分区名 + 作品数 + 均分 + 时间跨度）+ 3 列封面网格（页脚留白防裁切）；分页规则 = 每页 3×4=12 部，最后一页不足 12 时居中；黑白/彩色两套（`reduceMotion` 不影响静态图）。
- **效果**｜分区选择器 → 溢出菜单「生成本分区海报」，输出 1–N 页 PNG；页眉显示「2026 秋 · 12 部 · 均分 8.2」。
- **参考**｜本项目 `ui/share/ShareCardRenderer.kt` `[码]`；`anitabi/image-merge` 仅作图像合并思路 `[推断]`（未读源码）。
- **成本/风险**｜M｜封面缺失时必须有占位块，否则网格会破洞。
- **优先级**｜P1

### 8.6 评分对照卡（我 vs 社区）
- **现状**｜无 · 新提出｜详情页有「评分对比」「评分分布」，但它们只活在屏幕里（`RatingInsights`、`NirikoDonutChart`）。
- **提升**｜「我给它 9 分，全站只有 4% 的人给 9 分」这种信息天然适合传播；而且它把项目已有的 `RatingInsights`（个人 vs 社区偏离）从沉默的数字变成可分享的结论。
- **原理**｜数据 = 我的分 + 社区分 + `score_details` 分布 + 本地同类型百分位；版式 = 一条横向刻度（0–10）上放两个标记（我/社区），下方迷你分布柱；文案模板由纯函数生成（「你比平均高 1.3 分」）。
- **效果**｜详情页分享菜单新增「评分对照卡」；单作品，1 页。
- **参考**｜本项目 `data/calculator/RatingInsights.kt` `[码]`；`FuzzyGrim/Yamtrack@dev` 的评分统计口径 `[README]`。
- **成本/风险**｜S｜社区分缺失（新番、冷门）时降级为「暂无社区分」，不要画空刻度。
- **优先级**｜P2

### 8.7 追番周报卡（本周更新 + 我的进度）
- **现状**｜无 · 新提出｜4.3「未来七天」与 5.x 的周趋势都没做成可分享产物。
- **提升**｜周报是**周期性社交货币**：每周固定时间生成，用户有分享动机，应用有回访理由。且它完全由本地数据 + 放送日历生成，不需要任何账号。
- **原理**｜输入 = 本周（周一–周日）放送事件 ∪ 我的在看清单 + 本周进度增量；版式 = 顶部「10/13–10/19」+ 三行（本周更新 N 部 / 看掉 M 集 / 追完 K 部）+ 最期待的一部大图；生成时机 = 周日晚 20:00 之后首次打开统计页时若当周未生成则生成并提示。
- **效果**｜统计页顶部出现「本周周报已生成」；分享后图上有「Niriko 周报 · 第 42 周」。
- **参考**｜本项目 4.3 的聚合数据 + `ShareFlow` `[码]`。
- **成本/风险**｜S｜依赖 4.3 先落地；停播周会出现「0 部更新」的空周报 → 空周不生成。
- **优先级**｜P1
