# 批次 A 任务卡规范（Lead 下发）

每张任务卡固定 9 个字段，缺一不可：

```
## A-<编号> <标题>
- **问题**｜一句话现象 + 证据（file:line 或符号名，必须实际读过）
- **改哪里**｜文件 → 函数/类（含行号范围）
- **怎么改**｜3–7 步；涉及数据结构就写出字段/SQL/函数签名
- **测试**｜JVM 单测要覆盖的输入与断言（纯函数优先）
- **验收**｜真机/命令可执行的步骤与期望结果
- **风险/回滚**｜最可能翻车的点 + 怎么退回
- **预估**｜S（≤半天）/ M（1–2 天）
- **依赖**｜其他任务 ID 或「无」
```

附加要求：
1. **只读分析，不改任何代码**；只写分配给你的那一个 md。
2. 行号必须对得上当前工作区（读文件确认）；引用符号名要能在代码里 grep 到。
3. 如果一条任务会动 Room 表结构，在「怎么改」里显式写「v33 迁移：是/否」，并说明是否需要新增 DAO 方法。
4. 如果发现计划里的描述与代码不符（例如已经修过、位置不同），在任务卡顶部加一行 **⚠ 与计划不符** 并写清差异。
5. 任务之间若有隐含顺序（例如 D3 依赖 D4 的 baseline），写进「依赖」。
6. 排版用中文，代码/路径用反引号；每张卡 15–30 行。
