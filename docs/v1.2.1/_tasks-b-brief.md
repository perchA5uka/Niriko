# 批次 B 任务卡规范（Lead 下发）

目标：把 v1.2.1 批次 B（视觉与交互一致性 + 悬浮控件专项）拆成可独立验收的任务卡。**只读分析，不改代码。**

每张卡固定 9 字段：
```
## B-<编号> <标题>
- **问题**｜现象 + 证据（file:line，必须回代码确认）
- **改哪里**｜文件 → 函数/组件（行号范围）
- **怎么改**｜3–7 步，含关键参数（时长/阈值/token）
- **测试**｜JVM 单测或源码契约测试要点
- **验收**｜真机可执行的步骤与期望
- **风险/回滚**｜最可能翻车的点
- **预估**｜S/M/L
- **依赖**｜其他卡或「无」
```

批次 B 的硬约束：
1. **只改 UI 层**，不动数据层/Repository/同步；不需要 Room 迁移（v33 只服务批次 C）。
2. 不改导航架构、Dock 顺序/路由/尺寸/颜色/点击行为（悬浮专项尤其）。
3. 不新增依赖；不引入全局透明触摸层。
4. 每张卡都要写清「改动前/改动后的可观测差异」，不要写「优化体验」。
5. 与已完成的批次 A 冲突的地方（例如顶部内边距常量、Screens.kt 的骨架）要指出。
