# 评论区挖需求：泛式「7 月新番完结吐槽」评论区调研

> 调研日期：2026-11-08 · 目的：从真实观众的追番经历里，找 Niriko 该补什么
> 视频：BV1Uppw6yEMr《啊啊7月新番你到底给我下了什么药啊！！【泛式】》· 303.8 万播放 · 1.05 万评论

## 1. 样本与方法

- 采集：手机端哔哩哔哩 App 评论区，无障碍读取（网页 API 匿名只放 3 条/页，抓不全）。
- 范围：热门评论 10 页 + 热度续翻 12 页 + 最新评论 12 页，去重后约 **150 条**。
- 口径：**定性归纳**，样本约 1.5%，不是全量统计。点赞数只作代表性参考。

## 2. 评论区到底在聊什么

| 话题 | 占比感 | 典型内容 |
| --- | --- | --- |
| 作品口碑（某部番值不值） | 最多 | 「前面都稳，结尾一把赶完最难受」「七月最大黑马」 |
| 追番经历与心态 | 次多 | 「七月我一部没追，看完这期反而想去补了」「三十五岁失去热情」 |
| 求推荐 / 要片单 | 明显 | 「给个推荐 list 啊，我指着你推荐看番」 |
| 追番方式 | 少量但关键 | 「攒到最后一口气看完」「追番做的笔记也写了三份」 |
| 工具愿望 | 零星 | 「什么时候出看一遍让我投一次币的功能」 |

## 3. 需求池

### P0 · 小改动大收益

**R1 片单文本 → 一键生成待看清单**
- 证据：「大哥，虽然内容很棒，给个推荐 list 的啊！我都指着你的推荐看番，除了开头说的三部其他根本不知道推荐其他哪些！」（3 天前，上海）；「七月我一部没追，看完这期反而想去补了」
- 现状：无。发现页只有榜单，用户看到一段文字/一串番名仍要逐部手搜。
- 做法：粘贴一段文字 → 正则抽中日文/中文书名号与已知番名 → 用现有标题匹配对齐 Bangumi → 预览 → 批量加入「想看」。匹配失败的进「待确认」列表，允许手点。
- 依赖：标题匹配纯函数（README 已提到「匹配」抽成纯函数），不需新表，加一张临时清单表或直接落收藏。

**R3 完结口碑信号（烂尾预警）**
- 证据：「我没追这部，但『前面都稳，结尾一把赶完』这种最难受——像话说到一半被人关了灯」；「甚至看到第十集都觉得没有任何问题，可惜结尾真的太仓促」
- 现状：详情页有评分与评分对照，但没有「结局质量」这一维。
- 做法：完结作品显示评分分布（已有数据）+ 后 20% 集数评分曲线；给「结尾崩坏」打标由社区/本地标签承担，不做众包打分。

**R5 重看次数**
- 证据：「很多地方我反复观看了好几遍」「最后一段混剪看了四遍」；另一条直接许愿「什么时候出看一遍让我投一次币的功能」
- 现状：只有「看过」状态，没有次数。
- 做法：收藏加 rewatchCount（Room 加列 + 迁移），统计页加「重看最多」「今年重看 N 次」。

### P1 · 需要想清楚再动

**R2 从「点评/吐槽」直接落进想看的闭环**
- 证据：「只看了再见拉拉」「手气7月新番居然能被讲成这么完整的一篇，看完又想去补番了」
- 现状：要手动搜。R1 做好后顺带就有：抽出的条目直接带「加入想看」按钮。

**R6 攒番模式**
- 证据：「这种片子就是要攒到最后一口气看完，如果在后半段停下来，真的很要命」
- 现状：漏看提醒按「落后 ≥3 集」计数，对攒番用户是噪音。
- 做法：单部作品加「攒着看」标记 → 该作品不参与漏看提醒；完结时集中提示一次。统计里区分「周追」与「攒看」。

**R4 追番笔记从「单集」提升到「可检索」**
- 证据：「我也挑战看 30 部 7 月新番，但真是看不过来了，追番做的笔记也写了三份」
- 现状：单集笔记已有（feature-summary 已列入），但缺全文搜索与导出。
- 做法：笔记全文搜索、按作品聚合视图、导出 md/JSON。配套「批量调进度 / 批量放弃」解决「30 部看不过来」。

**R7 类似口味推荐（本地，不上服务器）**
- 证据：「有没有恋番推荐，最好类似《月色真美》《一周的朋友》……不要智斗和心机，男主懵懂、女主天真但不三无……（附自己整理的候选）」
- 现状：发现页按热度/评分，没有「像这部，但不要 XX」。
- 做法：用 Bangumi 标签 + 本地已看/评分做口味向量，支持排除词（不要 NTR / 不要胃疼 / 不要智斗）；结果仍走本地计算，符合「无服务器」约束。

### P2 · 想做但先放着

**R8 长期陪伴式回顾**：「十五岁的我说爱动画，二十五岁的也说，三十五岁彻底失去」——年度回顾已能做，可加「入坑第 N 年」「历年番单时间轴」。

**R11 内容警告（排雷）**：「我记得这番男主很人渣吧」「哇，还有排雷兵」——标签体系加一组内容警告，可订阅过滤。

### 明确不做

- **R9 评论区/讨论集成**：数据源与合规成本高，Niriko 无服务器，不做。分享走现有海报/周报卡。
- **R12 从切片（短视频）识别番**：需要视频理解，成本远超收益；R1 的粘贴解析已覆盖大半场景。

## 4. 和现有功能的对照（避免重复造）

| 评论诉求 | Niriko 现状 |
| --- | --- |
| 「今晚看什么」「这周哪几天更新」 | ✅ 统计页「今晚看什么」「接下来七天」 |
| 「落后三集提醒我」 | ✅ 漏看提醒（落后 ≥3 集） |
| 「记得看到第几集/第几卷」 | ✅ 收藏进度（含卷进度） |
| 「把番表导进日历」 | ✅ .ics 导出（本月/本季/在追） |
| 「某部番到底几分」 | ✅ 评分对照卡 + 权威评分 |
| 「给个片单」 | ❌ 缺（R1） |
| 「结尾烂不烂」 | ❌ 缺（R3） |
| 「我看了几遍」 | ❌ 缺（R5） |
| 「攒着一起看，别催我」 | ⚠️ 半（R6） |
| 「等完结再补」 | ⚠️ 半（状态有，缺集中提示） |

## 5. 最小落地切片建议

1. **R1 + R2 一起做**：粘贴片单 → 预览匹配 → 批量入「想看」，一次改动就把「看完这期想去补」的路径打通。
2. **R5 单独一个提交**：加列 + 迁移 + 统计卡，风险最低。
3. **R3 先只做展示**：不引入新数据源，先把评分分布和后段曲线画出来，观察是否有用再加标签。

## 6. 方法局限

- 只抽了约 150 条热门/最新评论，评论区长尾（1 万条）没覆盖；结论是方向性的，不是分布统计。
- 评论区是「完结吐槽」场景，天然偏作品评价而非工具使用；所以本报告把「工具缺口」从行为里反推，而不是等人直说。
