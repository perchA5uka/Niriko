# 详情页增强 / 关系图 / 分享卡 / 日历合并 · 原型与实施计划

> 产出：10 张布局原型（393×852 dp 手机页 + 1080×1440 分享卡），色值为示意，尺寸与层级全部取自仓库现有 token。
> 原型文件：`prototypes/png/`、`prototypes/svg/`；手机存储副本：`/sdcard/Download/DSH-Go/原型/`。

## 0. 审美基线：先对齐既有系统，而不是另起一套

没有参考图时，最容易做错的是「凭感觉配色和定字号」。所以我用五步把审美锚在代码里：

1. **只取仓库现有 token**：圆角只有 20 / 16 / 12 / 999 四档（`NirikoShapes`）；字号只取 `Type.kt` 的层级（28 标题 / 16 区块 / 15 列表 / 13 正文 / 11.5 元信息）；强调色不新增，图表色一律走 `ChartPalette`（由主题 primary 派生 6 色）。
2. **拿已通过的样本当基准**：`ShareCardVariants` 的三张卡（1080×1400 / 1080×1080）是已上线且经过评审的排版，新卡沿用它的外边距（72px）、标题字阶与底部品牌区，不重新发明。
3. **三档密度对照再选**：每屏先出「稀疏 / 默认 / 密集」三种信息密度，默认取中间档——手机上一屏超过 3 个区块就没人看。
4. **硬规则替代主观判断**：正文对比度 ≥ 4.5:1（项目已有 WCAG 校验）、单卡正文 ≤ 7 行、分享卡封面占比 ≥ 55%。
5. **用真机截图校准**：改完后截图缩到 393 宽与原型并排比间距，差 8dp 以上的地方都算 bug。

这套方法的本质是：**把「好看」翻译成可检查的约束**，评审时只说违反哪条，不用争审美。

## 2. 逐项方案

### 2.1 关联作品 → 关系图（需求 1）
- 入口：`关联作品` 组件标题行右侧放 28dp 胶囊按钮（图标 ◈）+ 文字「关系图」，点击进次级页。
- 次级页结构：顶部筛选 chips（全部/本篇/前作/续作/衍生）→ 画布（当前作品居中，卫星节点环绕，虚线边）→ 底部说明条（双指缩放 / 长按看简介 / 重置）。
- 交互：点任意节点把它变成中心并重排（带动画）；关系超过 20 个节点时按「一层」截断，显示「还有 N 个」。
- 数据：直接复用本地已缓存的关联作品列表，不新增表；布局用简单力导向或环形布局（纯函数，可单测）。
- 验收：9 个关联的作品渲染 < 200ms；无关联时显示空态而不是空白画布。

### 2.2 完整角色数据（需求 2）
- 详情页新增 `完整角色数据` 区块：每行「头像 / 角色名 / CV / 角色定位 + 出场话数」，右侧 chevron 进角色页。
- 角色页包含：头图区（头像 96 + 名 + 原名 + 标签）、`出场作品` 列表、`声优` 卡（同 CV 角色入口）、`角色关系` 预览 + 关系图入口。
- 数据：Bangumi 角色接口（含 CV 与 role），24h 缓存沿用 `DetailCacheStore` 口径；缺数据的字段整行隐藏，不留「暂无」。
- 验收：角色页冷启动 < 1.2s；无 CV 的角色不显示空标签。

### 2.3 角色关系图（需求 3）
- 入口：角色页标题右侧「关系图 ◈」+ 作品详情页角色区块的「完整数据 ›」。
- 结构：中心角色 + 环绕节点，边中点放关系类型小胶囊（家人/同学/对手/师生）。
- 与作品关系图共用同一个画布组件，差别只在节点渲染器与图例文案。

### 2.4 「接下来七天」合并日历周视图（需求 4）
- 日历页的「周」视图改为复用统计页的「接下来七天」组件，删掉两套实现。
- 每天一列：星期 / 日期 / 封面叠放（最多 3 层）/ 更新数；今天用主题色高亮。
- 交互：点日期列 → 该列下方展开当天更新列表（高度动画 220ms + 淡入），再点收起；与日历页现有的「点日期展开」动效同一规格。
- 验收：两处入口的数据口径一致（同一 `AirTime` 换算）；展开后列表可滑动且不顶掉顶部卡片。

### 2.5 日历分享卡（需求 5）
- 1080×1440：月份大字标题 + 7 列日历网格（类型色圆点）+ 今日高亮 + 底部三项统计 + 品牌区。
- 数据：`CalendarShareCardData`（月份、每日更新数、类型分布、在追/漏看计数），复用手写渲染桥 `ShareBitmapHost.renderContent`。
- 验收：无更新的月份不生成空卡；深色主题下自动切深色底。

### 2.6 作品信息分享卡 + 我的收藏卡（需求 6）
- 作品卡：全幅封面（上 57%）+ 底部渐变 + 标题/原名/评分/标签 + 「我的一句话」+ 进度条 + 品牌区。比旧版多「我的短评」和进度，少一排外部源。
- 收藏卡：深色底，年度标题 + 三个计数 + 4×2 封面网格 + 年度关键词 + 二维码位。
- 单作品收藏卡（新增）：状态胶囊 + 星级 + 标签 + 短评 + 追番轨迹三节点 + 用时统计。
- 验收：封面加载失败时用主题色占位，不留白块；长标题最多 2 行省略。

### 2.7 Kazumi 传送门（需求 7）
- 底部主按钮「传送门」→ 先尝试 `kazumi://` 深链（带作品名 + 集数），失败回退到应用市场页；未安装时按钮文案改为「去下载 Kazumi」。
- 点击前若已有进度，弹出一次「从第 N 话开始」的确认，避免误跳。
- 验收：已装/未装/深链失败三种状态都有明确反馈，不出现白屏或静默失败。

### 2.8 传送门 / 收藏编辑按钮改造（需求 8）
- 编辑收藏从底部条移到右上角 28dp 胶囊组（编辑 / 分享 / 更多），形状由圆角矩形改 999 胶囊；底部只留「传送门」主按钮 + 收藏状态胶囊。
- 依据：底部两个等宽按钮会让「主操作」和「进入设置」权重相同；改后主按钮独占左半边，右侧状态胶囊只读。

## 7. 决策记录与库选型（2026-11-08）

### 7.1 已拍板

1. 关系图：**支持递归展开**，并且要**同时展示所有角色间的相互关系**（不是星形辐射）。
2. 角色数据：**只用 Bangumi**，不接 AniList。
3. 分享卡：**不要二维码**，底部只留文字品牌区。
4. 日历的「周」标签页：合并后**直接删除**。

### 7.2 现成库调研（按新规则：先查再写）

| 需求点 | 候选 | 结论 | 理由 |
| --- | --- | --- | --- |
| 网络图渲染 | `dev.bandb.graphview:graphview` 0.8.1 | 不采用 | Android View 体系，需 `AndroidView` 包一层；无递归/全关系模式；发布停在 0.8.1 |
| 网络图渲染 | `com.jjoe64:graphview` 4.2.2 | 不适用 | 折线/柱状图表，不是节点关系图 |
| 布局算法 | `Samuelk0nrad/sociogram`（KMP，Fruchterman-Reingold） | 仅作算法参考 | 只提供布局，无 Compose 渲染与手势 |
| Maven 全量检索 | `force graph` / `network graph` / `compose graph` | 无可用的 JVM/Compose 网络图库 | 命中只有 webjars 的 JS `force-graph` |
| 分享卡渲染 | 仓库已有 `ShareBitmapHost` + `ShareCardVariants` | 复用 | 1080×1400 渲染管线已跑通，无需引入图片合成库 |
| 缩放平移 | Compose `detectTransformGestures`（官方） | 采用 | 无需第三方 |
| Kazumi 深链 | `Intent` + `PackageManager` 探测 | 自研 | 无库需求，几行代码 |

**结论**：关系图自研 Compose Canvas + 力导向布局，预计 300–400 行（含纯函数布局与单测）。不引入新依赖，符合「无 DI、纯函数优先」的现有约定。

### 7.3 数据可行性（关键风险）

- Bangumi v0 `/v0/characters/{id}` **实测没有 `relations` 字段**（返回只有 name/images/infobox/stat 等）。
- 旧版 `/character/{id}?responseGroup=large` 现在返回错误体（`request/code/error`），不可用。
- 唯一可用来源：`bgm.tv/character/{id}` 页面的**「关联角色」区块**，实测包含关系标签（如「朋友」「形态」）+ 角色 id + 名字 + 头像 URL。
- 所以角色关系必须走 **HTML 解析 + 本地缓存**：打开角色页时按需抓取、24h 缓存、解析失败自动降级为「只看直连（同作品共演）」。
- 因此需求 3 的工期比原计划多 2–3 天，且需要一条「解析层失效」的降级路径与单测夹具（保存真实 HTML 快照）。

### 7.4 原型更新

- `04-角色关系图` 已改为**全关系模式**：画出角色之间的交叉边，顶部提供「只看直连 / 全部关系 / 展开两层」三档切换，图例说明不是星形辐射。
